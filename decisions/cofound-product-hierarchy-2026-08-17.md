# CO.FOUND — Product Hierarchy Lock

This decision corrects a hierarchy mistake made during the 2026-08-17 Founder Intelligence / CO.FOUND discussion.

## LOCKED HIERARCHY

**CO.FOUND is the operating intelligence environment itself. It does not live under Co.Lab.**

Co.Lab, LastBench, Class A, and future ventures live **inside CO.FOUND** as company / venture spaces.

### Product stack

1. **CO.FOUND** — the top-level operating environment for building, navigating, learning through, and remembering companies.
2. **Founder Intelligence** — the reasoning / navigation / memory engine inside CO.FOUND.
3. **Human interaction modes** — ROOM, MAP, FOCUS, ASK, Replay, Pre-Live, Learning/Momentum interactions.
4. **Company / venture spaces** — Co.Lab, LastBench, Class A, and future businesses.
5. **Integrated operating sources** — calendar, meetings, tasks, CRM, finance, documents, communication, GitHub, and other approved sources.

## IMPORTANT BRANDING CONSEQUENCE

Do not use `CO.FOUND by Co.Lab` as the primary product hierarchy if that wording implies CO.FOUND is a sub-product of Co.Lab.

Co.Lab may still be referenced historically as an originator / creator / implementation partner where useful, but inside the operating model it is a company space running on CO.FOUND.

## PRODUCT SOUL ADDITION

CO.FOUND is not only about making the company smarter. It should help the people building the company become more capable through the work itself.

Core loop:

`real work -> capability gap -> learn -> practice -> apply -> result -> skill evidence -> company progress + human progress`

This makes learning a product principle from day one even when the full learning/capability UI is deferred.

Class A can contribute capability content, frameworks, or interventions, but the **Learning / Capability Engine is a CO.FOUND platform capability**, not something that makes CO.FOUND subordinate to Class A or Co.Lab.

## MOTIVATION / MOMENTUM PRINCIPLE

CO.FOUND should make progress compelling through meaningful feedback:

- routes unlock;
- blockers disappear;
- milestones activate;
- skills become proven;
- company state visibly changes;
- team capability grows;
- real impact becomes visible.

Do not reduce this to meaningless XP, compulsive dark patterns, or claims that the product treats ADHD. Design instead for low cognitive load, immediate feedback, short missions, visible progress, adaptive challenge, and neuroinclusive attention support.

## MENTAL MODEL

CO.FOUND should feel like navigation for building a company:

`You are here -> destination -> available routes -> blocker -> alternative route -> skill/capability needed -> action -> progress -> learn -> recalculate`

Replay answers `Where have we been and what did we learn?`

Pre-Live answers `What could happen if we take this route?`

## COMPANY-SPACE EXAMPLE

CO.FOUND
- Co.Lab
- LastBench
- Class A
- Future venture A
- Future venture B

Each space has its own goals, money, people, work, decisions, outcomes, and history while CO.FOUND can model shared founders, shared capital, shared capabilities, and relationships across spaces when permission and evidence support it.

## NON-CHANGE

This hierarchy correction does not replace the current Founder Intelligence architecture. ROOM / MAP / FOCUS / ASK, Visual Action Branches, Detour, Decision -> Outcome Memory, Replay, Pre-Live, provenance, correction-first capture, money truth, and the staged LastBench pilot remain intact unless real evidence later changes them.
