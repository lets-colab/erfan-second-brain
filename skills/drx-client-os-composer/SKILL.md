# DR.X Client OS Composer

## Goal
Build one client-facing home that feels like a control room, not a document dump.

## Composition model
Use these layers in order unless evidence strongly justifies otherwise:
1. `EXECUTIVE COMMAND CENTER` — current status, previous benchmark, one-sentence diagnosis.
2. `PERFORMANCE FUNNEL` — acquisition -> response -> conversion -> attendance -> retention.
3. `DEPARTMENTAL DELIVERY` — what was built, why it exists, current state, measurable result.
4. `LIVE OPERATIONS` — pipeline, CRM, profile/campaign tracking, owners, next actions.
5. `EXPERIENCE SHOWCASE` — visual cards/gallery for shipped customer-facing modules such as RSVP, reward wheel, passes, menus, landing pages.
6. `REPORTS & EVIDENCE` — monthly reports, QA, reconciliation, source controls behind drill-downs.

## Departmentalization rule
Every material deliverable belongs to a business category, for example:
- Growth & Website
- Creator & Community
- Guest / RSVP
- Operations
- Data & Reporting
- Automation / Technology

Each department answers four questions:
`WHAT WE BUILT | WHY | STATUS | RESULT/NEXT PROOF`

## Reference transfer
When given benchmark workspaces such as LFG Campaign Workspace or Cortex:
- extract the transferable pattern;
- state what problem the pattern solves;
- adapt it to the current client's needs;
- do not copy structure that creates duplicate front doors or irrelevant clutter.

## Proof-of-work rule
Do not merely link to shipped experiences. Where the platform permits, use gallery cards, previews, embeds, screenshots, or clean visual links so management can see the work without leaving the page.

## One-front-door rule
There is exactly one client home. Child reports/databases are modules and drill-downs, not competing destinations.

## Density rule
Executive layer is sparse. Operating layer can be dense. Evidence layer may be exhaustive but collapsed.
